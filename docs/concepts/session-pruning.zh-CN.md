会话修剪在每次 LLM 调用之前裁剪上下文中的**旧工具结果**。它减少了由于积累的工具输出（exec 结果、文件读取、搜索结果）导致的上下文膨胀，而无需重写正常的对话文本。

<Info>
修剪仅在内存中进行——它不修改磁盘上的会话记录。你的完整历史记录始终被保留。
</Info>

## 为什么重要

长会话会积累膨胀上下文窗口的工具输出。这会增加成本，并可能使[压缩](/concepts/compaction)比必要的更早发生。

修剪对于 **Anthropic 提示缓存**尤其有价值。在缓存 TTL 到期后，下一个请求会重新缓存完整提示。修剪减少了缓存写入大小，直接降低成本。

## 工作原理

1. 等待缓存 TTL 到期（默认 5 分钟）。
2. 查找正常修剪的旧工具结果（对话文本保持不变）。
3. **软裁剪**过大的结果——保留头部和尾部，插入 `...`。
4. **硬清除**其余部分——用占位符替换。
5. 重置 TTL，以便后续请求重用新鲜缓存。

## 旧版图像清理

OpenClaw 还为在历史记录中保留原始图像块或提示水化媒体标记的会话构建单独的幂等重放视图。

- 它逐字节地保留**最近 3 个已完成轮次**，以便最近后续跟进的提示缓存前缀保持稳定。
- 在重放视图中，来自 `user` 或 `toolResult` 历史记录的旧已处理图像块可以被替换为 `[image data removed - already processed by model]`。
- 旧的文本媒体引用，如 `[media attached: ...]`、`[Image: source: ...]` 和 `media://inbound/...`，可以被替换为 `[media reference removed - already processed by model]`。当前轮次的附件标记保持完整，以便视觉模型仍然可以水化新鲜图像。
- 原始会话记录不被重写，因此历史记录查看器仍然可以渲染原始消息条目及其图像。
- 这与正常的缓存 TTL 修剪是分开的。它的存在是为了阻止重复的图像有效载荷或过时的媒体引用在后续轮次破坏提示缓存。

## 智能默认值

OpenClaw 为 Anthropic 配置文件自动启用修剪：

| 配置文件类型                                         | 修剪已启用 | 心跳    |
| ---------------------------------------------------- | ---------- | ------- |
| Anthropic OAuth/令牌身份验证（包括 Claude CLI 重用） | 是         | 1 小时  |
| API 密钥                                             | 是         | 30 分钟 |

如果你设置了明确的值，OpenClaw 不会覆盖它们。

## 启用或禁用

对于非 Anthropic 提供商，修剪默认关闭。要启用：

```json5
{
  agents: {
    defaults: {
      contextPruning: { mode: "cache-ttl", ttl: "5m" },
    },
  },
}
```

要禁用：设置 `mode: "off"`。

## 修剪与压缩

|            | 修剪           | 压缩           |
| ---------- | -------------- | -------------- |
| **内容**   | 裁剪工具结果   | 摘要对话       |
| **已保存** | 否（每次请求） | 是（在记录中） |
| **范围**   | 仅工具结果     | 整个对话       |

它们互为补充——修剪在压缩周期之间保持工具输出精简。
