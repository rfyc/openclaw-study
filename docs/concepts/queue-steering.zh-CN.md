当消息在会话运行已处于流式传输状态时到达时，OpenClaw 可以将该消息发送到活跃运行时，而不是为同一会话启动另一个运行。公共模式与运行时无关；Pi 和原生 Codex 应用服务器测试框架以不同方式实现投递细节。

## 运行时边界

转向不会中断已在运行的工具调用。Pi 在模型边界检查已排队的转向消息：

1. 助手请求工具调用。
2. Pi 执行当前助手消息的工具调用批次。
3. Pi 发出轮次结束事件。
4. Pi 清空已排队的转向消息。
5. Pi 在下一次 LLM 调用之前将这些消息追加为用户消息。

这将工具结果与请求它们的助手消息配对，然后让下一次模型调用看到最新的用户输入。

原生 Codex 应用服务器测试框架公开 `turn/steer` 而不是 Pi 的内部转向队列。OpenClaw 在那里适配相同的模式：

- `steer` 在配置的静默窗口内批处理已排队的消息，然后发送一个按到达顺序包含所有收集的用户输入的 `turn/steer` 请求。
- `queue` 通过发送单独的 `turn/steer` 请求来保持旧版序列化形状。
- `followup`、`collect`、`steer-backlog` 和 `interrupt` 保持在活跃 Codex 轮次周围的 OpenClaw 自有队列行为。

Codex 审查和手动压缩轮次拒绝同轮次转向。当运行时无法接受转向时，OpenClaw 在该模式允许的情况下回退到后续队列。

本页解释正常入站消息的队列模式转向。有关显式的 `/steer <message>` 命令，请参见 [Steer](/tools/steer)。

## 模式

| 模式            | 活跃运行行为                                                                              | 后续跟进行为                                         |
| --------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `steer`         | 在下一个运行时边界一起注入所有已排队的转向消息。这是默认值。                              | 仅当转向不可用时才回退到跟进。                       |
| `queue`         | 旧版逐一转向。Pi 在每个模型边界注入一条已排队的消息；Codex 发送单独的 `turn/steer` 请求。 | 仅当转向不可用时才回退到跟进。                       |
| `steer-backlog` | 与 `steer` 相同的活跃运行转向行为。                                                       | 还为后续跟进轮次保留相同的消息。                     |
| `followup`      | 不转向当前运行。                                                                          | 稍后运行已排队的消息。                               |
| `collect`       | 不转向当前运行。                                                                          | 在防抖窗口后将兼容的已排队消息合并到一个后续轮次中。 |
| `interrupt`     | 中止活跃运行，然后启动最新消息。                                                          | 无。                                                 |

## 突发示例

如果四个用户在智能体执行工具调用时发送消息：

- `steer`：活跃运行时在其下一次模型决策之前按到达顺序接收所有四条消息。Pi 在下一个模型边界清空它们；Codex 将它们作为一个批处理的 `turn/steer` 接收。
- `queue`：旧版序列化转向。Pi 一次注入一条已排队的消息；Codex 接收单独的 `turn/steer` 请求。
- `collect`：OpenClaw 等待活跃运行结束，然后在防抖窗口后使用兼容的已排队消息创建一个跟进轮次。

## 范围

转向始终针对当前活跃的会话运行。它不创建新会话、不更改活跃运行的工具策略，也不按发送者拆分消息。在多用户频道中，入站提示已经包含发送者和路由上下文，因此下一次模型调用可以看到每条消息的发送者。

当你想要 OpenClaw 构建一个可以合并兼容消息并保留后续队列丢弃策略的后续跟进轮次时，使用 `collect`。仅在需要较旧的逐一转向行为时使用 `queue`。

## 防抖

`messages.queue.debounceMs` 适用于后续跟进投递，包括 `collect`、`followup`、`steer-backlog` 以及当活跃运行转向不可用时的 `steer` 回退。对于 Pi，活跃的 `steer` 本身不使用防抖计时器，因为 Pi 自然在下一个模型边界之前批处理消息。对于原生 Codex 测试框架，OpenClaw 在发送批处理的 `turn/steer` 之前使用与静默窗口相同的防抖值。
