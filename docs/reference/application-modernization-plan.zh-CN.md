# 应用现代化计划

## 目标

在不破坏当前工作流或在宽泛重构中隐藏风险的前提下，使应用朝着更简洁、更快速、更易维护的方向发展。工作应以小型可审查的切片方式进行，并为每个涉及的界面提供验证。

## 原则

- 除非某个边界明显造成混乱、性能损耗或用户可见的 bug，否则保留当前架构。
- 对每个问题优先使用最小的正确补丁，然后重复。
- 将必要修复与可选优化分开，以便维护者可以在无需等待主观决策的情况下完成高价值工作。
- 保持插件面向行为的文档记录和向后兼容。
- 在声称回归已修复之前，验证已发布的行为、依赖合约和测试。
- 首先改善主要用户路径：入门引导、认证、聊天、提供商设置、插件管理和诊断。

## 第一阶段：基线审计

在更改之前对当前应用进行清点。

- 识别顶级用户工作流及其拥有的代码界面。
- 列出无效功能、重复设置、不清晰的错误状态和昂贵的渲染路径。
- 为每个界面捕获当前验证命令。
- 将问题标记为必需、推荐或可选。
- 记录需要所有者审查的已知阻塞项，特别是 API、安全、发布和插件合约变更。

完成定义：

- 一份包含仓库根文件引用的问题列表。
- 每个问题都有严重程度、所有者界面、预期用户影响和建议的验证路径。
- 必需修复中不混入推测性清理项目。

## 第二阶段：产品和用户体验清理

优先处理可见工作流并消除混乱。

- 围绕模型认证、网关状态和插件设置收紧入门引导文案和空状态。
- 删除或禁用无法操作的无效功能。
- 在支持的响应宽度下保持重要操作可见，而不是将其隐藏在脆弱的布局假设后面。
- 合并重复的状态语言，使错误有单一的真相来源。
- 为高级设置添加渐进式披露，同时保持核心设置的快速访问。

推荐验证：

- 首次运行设置和现有用户启动的手动幸福路径。
- 针对任何路由、配置持久化或状态推导逻辑的专项测试。
- 变更响应式界面的浏览器截图。

## 第三阶段：前端架构强化

在不进行广泛重写的情况下提高可维护性。

- 将重复的 UI 状态转换移入狭窄的类型化辅助函数。
- 保持数据获取、持久化和展示职责分离。
- 优先使用现有的钩子、存储和组件模式，而非新的抽象。
- 仅在减少耦合或明确测试时拆分过大的组件。
- 避免为本地面板交互引入广泛的全局状态。

必要防护措施：

- 不要将文件分割作为副作用来更改公开行为。
- 保持菜单、对话框、选项卡和键盘导航的无障碍行为完整。
- 验证加载、空状态、错误和乐观状态仍然可以渲染。

## 第四阶段：性能和可靠性

针对已测量的痛点而非广泛的理论优化。

- 测量启动、路由切换、大型列表和聊天记录的开销。
- 在性能分析证明有价值的地方，用记忆化选择器或缓存辅助函数替换重复的昂贵派生数据。
- 减少热路径上不必要的网络或文件系统扫描。
- 在模型负载构建之前，保持提示词、注册表、文件、插件和网络输入的确定性排序。
- 为热路径辅助函数和合约边界添加轻量级回归测试。

完成定义：

- 每个性能变更记录基线、预期影响、实际影响和剩余差距。
- 当有便宜的测量方式时，不允许仅凭直觉提交性能补丁。

## 第五阶段：类型、合约和测试强化

提高用户和插件作者所依赖的边界点的正确性。

- 用判别联合或封闭代码列表替换松散的运行时字符串。
- 使用现有的模式辅助函数或 zod 验证外部输入。
- 围绕插件清单、提供商目录、网关协议消息和配置迁移行为添加合约测试。
- 将兼容性路径保留在 doctor 或修复流程中，而非启动时隐藏的迁移。
- 避免测试与插件内部的耦合；使用 SDK 外观和已记录的桶文件。

推荐验证：

- `pnpm check:changed`
- 针对每个变更边界的专项测试。
- 当延迟边界、打包或已发布界面变更时执行 `pnpm build`。

## 第六阶段：文档和发布准备

保持面向用户的文档与行为一致。

- 随行为、API、配置、入门引导或插件变更更新文档。
- 仅为用户可见的变更添加变更日志条目。
- 保持插件术语面向用户；仅在贡献者必要的地方使用内部包名。
- 确认发布和安装说明仍与当前命令界面匹配。

完成定义：

- 相关文档在与行为变更相同的分支中更新。
- 触及时，生成的文档或 API 漂移检查通过。
- 交接时说明任何跳过的验证及其跳过原因。

## 推荐首个切片

从有范围的控制 UI 和入门引导改进开始：

- 审计首次运行设置、提供商认证就绪、网关状态和插件设置界面。
- 删除无效操作并明确故障状态。
- 为状态推导和配置持久化添加或更新专项测试。
- 运行 `pnpm check:changed`。

这在有限的架构风险下提供了高用户价值。

## 前端技能更新

使用本节更新现代化任务附带的面向前端的 `SKILL.md`。如果将此指导作为仓库本地 OpenClaw 技能采用，首先创建 `.agents/skills/openclaw-frontend/SKILL.md`，保留属于该目标技能的 frontmatter，然后添加或替换正文指导为以下内容。

```markdown
# 前端交付标准

在实现或审查面向用户的 React、Next.js、桌面 WebView 或应用 UI 工作时使用此技能。

## 操作规则

- 从现有产品工作流和代码约定开始。
- 优先使用改善当前用户路径的最小正确补丁。
- 在交接中将必需修复与可选优化分开。
- 当请求是应用界面时，不要构建营销页面。
- 在支持的视口尺寸下保持操作可见且可用。
- 删除无效功能，而非保留无法操作的控件。
- 保留加载、空状态、错误、成功和权限状态。
- 在添加新基础元素之前，使用现有设计系统组件、钩子、存储和图标。

## 实现清单

1. 确定主要用户任务及其拥有的组件或路由。
2. 编辑前先阅读本地组件模式。
3. 修补解决问题的最小界面。
4. 为固定格式的控件、工具栏、网格和计数器添加响应式约束，使文本和悬停状态不会意外地调整布局大小。
5. 保持数据加载、状态推导和渲染职责清晰。
6. 当逻辑、持久化、路由、权限或共享辅助函数更改时添加测试。
7. 验证主幸福路径和最相关的边缘情况。

## 视觉质量门控

- 文字必须在移动端和桌面端都适合其容器。
- 工具栏可以换行，但控件必须保持可访问。
- 当图标比文字更清晰时，按钮应使用熟悉的图标。
- 卡片应用于重复项目、模态框和带框工具，而非每个页面部分。
- 避免单调的色调和与操作内容竞争的装饰性背景。
- 密集的产品界面应优化扫描、比较和重复使用。

## 交接格式

报告内容：

- 更改了什么。
- 用户行为发生了什么变化。
- 通过了哪些必需验证。
- 跳过了哪些验证及具体原因。
- 可选的后续工作，与必需修复明确分开。
```
