# 嵌入式运行器测试性能

嵌入式尝试运行器是最昂贵的智能体测试层面之一。仅在行为真正需要运行器时才使用完整运行器测试。

## 护栏规则

- 对于提示组装、运行时上下文构造、缓存元数据、token 计量和维护决策逻辑，优先使用专注的辅助工具测试。
- 对于无法通过辅助工具证明的跨组件行为保留完整 `runEmbeddedAttempt` 覆盖，而非用于单一派生字段。
- 从运行器逻辑中提取辅助工具时，让生产代码直接调用该辅助工具，然后测试辅助工具。避免测试专用的运行器行为副本。
- 在精简测试时，为 `sessionKey`、`sessionFile`、token 预算、当前 token 数量、提示缓存和路由字段保留上下文引擎覆盖。
- 对超过几秒的独立完整运行器测试保持怀疑。首先问一下证明是否可以移至生产辅助工具加一个廉价的集成冒烟测试。

## 验证

- 对于运行器测试精简，运行被修改的辅助工具测试和最近的两文件运行器/上下文引擎层面。
- 当变更以性能为目的时，记录 Vitest 持续时间、实际时间和 RSS。
