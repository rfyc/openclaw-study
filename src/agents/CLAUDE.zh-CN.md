# 智能体测试性能

智能体测试通常受限于导入耗时。将缓慢的测试文件视为架构信号，而不仅仅是测试运行器的噪声。

## 护栏规则

- 性能编辑前后均需进行基准测试。比较测试套件时优先使用现有的分组产物，或使用 `/usr/bin/time -l pnpm test <file>` 进行范围性热点分析。
- 如果测试只需要 schema、能力、路由或静态发现数据，不要冷加载完整的捆绑插件/通道/提供商运行时。添加或复用轻量级类型化产物，并将完整运行时作为回退保留。
- 将昂贵的引导、嵌入式运行器、提供商、插件和通道运行时工作置于依赖注入或窄型辅助工具之后，以便测试无需启动整个运行时即可覆盖行为。
- 对智能体热路径中的通道/插件查找持怀疑态度。如果代码只需要目标解析、对等类型推断、设置提示或静态描述符，在调用 `getChannelPlugin()` / 捆绑运行时回退之前，优先使用本地纯辅助工具或轻量级公共产物。
- 在 spawn/session/requester-origin 逻辑中，保持路由和交付上下文规范化的确定性和无运行时依赖。为通道特定前缀添加显式解析器覆盖，而非仅为分类目标而加载通道插件。
- 将慢速集成测试中的覆盖迁移出去时，在命名辅助工具中保留精确的生产组合并测试该辅助工具。不要仅因为旧的证明很慢就删除行为证明。
- 避免在热智能体测试中使用宽泛的 `importOriginal()` 局部 mock 和模块重置。使用显式 mock 工厂、一次性导入，并且只重置测试变更的状态。

## 验证

- 对于智能体性能变更，在交接或基准报告中记录变更前后的秒数和 RSS。
- 如果变更涉及惰性加载、插件运行时导入或捆绑产物，运行 `pnpm build`。
