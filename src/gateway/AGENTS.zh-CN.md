# Gateway 热路径

Gateway 服务器测试和启动路径在只需要插件拥有的静态描述符时，不应实例化捆绑插件运行时。

## 护栏规则

- 对于插件拥有的 Gateway 行为（如认证绕过路径），在回退到完整通道插件之前，优先使用轻量级公共产物解析器。
- 保持完整插件契约和轻量级产物由同一个插件拥有的辅助工具支撑，以防行为出现分歧。
- 不要从 Gateway HTTP/服务器代码加载宽泛的捆绑通道注册表仅为回答静态问题。
- 添加新的插件拥有的 Gateway 描述符时，在同一变更中添加核心解析器、插件产物和镜像的完整插件导出。
- 在 Gateway 服务器测试中，当被测行为不需要新的连接/认证握手时，复用套件级服务器、已认证的上下文和客户端。显式重置运行时状态，而不是每次测试重启整个服务器。
- 在手动 RPC 测试中保持调度器、轮询器和后台循环禁用，除非测试专门证明自动调度或生命周期行为。

## 验证

- 使用 `pnpm test <file>` 对受影响的 Gateway 测试文件进行变更前后的基准测试。
- 更改 Gateway 惰性加载或捆绑插件产物时运行 `pnpm build`。
