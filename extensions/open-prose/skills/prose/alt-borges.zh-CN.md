# OpenProse Borges 备选方案

一个潜在的 OpenProse 备选语言方案，从豪尔赫·路易斯·博尔赫斯的文学宇宙汲取灵感：无限图书馆、分岔的路径、循环的梦境和形而上学的迷宫。保留此文档用于与功能性语言进行未来基准测试。

## 关键词对照

### 代理与持久性

| 功能语言 | Borges      | 含义                                                   |
| -------- | ----------- | ------------------------------------------------------ |
| `agent`  | `dreamer`   | 短暂的，为某目的而创造（《环形废墟》：被梦想成真）     |
| `keeper` | `librarian` | 持久的，记忆，编目（《巴别图书馆》：无限知识的守护者） |

```prose
# Functional
agent executor:
  model: sonnet

keeper captain:
  model: opus

# Borges
dreamer executor:
  model: sonnet

librarian captain:
  model: opus
```

### 调用模式

```prose
# Functional
session: executor
  prompt: "Do task"

captain "Review this"
  context: work

# Borges
garden: dreamer executor
  prompt: "Do task"

captain "Review this"    # librarian invocation (same pattern)
  aleph: work
```

## 支持 Borges 的理由

1. **无限递归**：博尔赫斯的主题与计算递归对应（`circular`、`fork`）
2. **形而上学精确性**：`aleph`（所有上下文）等概念哲学上非常丰富
3. **图书馆隐喻**：`librarian` 完美捕捉了持久知识
4. **分岔路径**：`fork`/`path` 自然表达了并行执行和选择
5. **梦境逻辑**：`dreamer` 暗示创造和短暂性
6. **文学连贯性**：所有术语来自统一的文学宇宙
7. **自我指涉**：博尔赫斯钟爱自我指涉；契合编程的递归本质

## 反对 Borges 的理由

1. **文化门槛**：需要对博尔赫斯作品有深度了解
2. **抽象性**：`aleph`、`hexagon` 对实际使用可能太抽象
3. **重载问题**：`fork` 可能引起混淆（Unix fork 与 path fork）
4. **风格不匹配**：语言其余部分是功能性的（`session`、`parallel`、`loop`）
5. **可访问性**：对大多数用户违反了"不言而喻"的原则
6. **名词混淆**：`garden` 作为类动词结构可能很别扭
7. **翻译负担**：不熟悉博尔赫斯的非英语用户会有困难

## 结论

保留用于基准测试。功能性语言（`agent`/`keeper`）是当前的主要路径。Borges 提供了丰富的隐喻，但代价是可访问性和不言自明性。

## 关于博尔赫斯影响的说明

博尔赫斯的作品预见了许多计算概念：

- **无限递归**：《环形废墟》、《巴别图书馆》
- **平行宇宙**：《小径分岔的花园》
- **自我指涉**：许多故事包含自身
- **信息论**：《巴别图书馆》作为无限信息空间
- **组合学**：图书馆中所有可能的书籍

这个备选方案向这一联系致敬，同时承认它对实际使用来说可能过于深奥。
