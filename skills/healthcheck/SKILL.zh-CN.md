# OpenClaw 主机安全加固

## 概述

评估并加固运行 OpenClaw 的主机，然后在不中断访问的前提下将其对齐到用户定义的风险容忍度。将 OpenClaw 安全工具作为首要信号，但将 OS 加固视为单独的、明确的步骤集合。

## 核心规则

- 建议使用最先进的模型运行本技能（如 Opus 4.5、GPT 5.2+）。代理应自查当前模型，若低于该水平则建议切换；但不阻止执行。
- 任何改变状态的操作都需要明确批准。
- 未确认用户的连接方式之前，不修改远程访问设置。
- 优先采用可逆的、分阶段的变更并制定回滚方案。
- 切勿声称 OpenClaw 会更改主机防火墙、SSH 或 OS 更新；它不会。
- 如果角色/身份未知，仅提供建议。
- 格式要求：每组用户选项必须编号，以便用户用单个数字回复。
- 建议进行系统级备份；尽量验证备份状态。

## 工作流程（按顺序执行）

### 0）模型自检（非阻断）

开始前检查当前模型。如果低于最先进水平（如 Opus 4.5、GPT 5.2+），建议切换。不阻止执行。

### 1）建立上下文（只读）

在询问之前，尽量从环境中推断 1-5 项。如需确认，优先提出简单、非技术性的问题。

按顺序确定：

1. OS 和版本（Linux/macOS/Windows），容器 vs 主机。
2. 权限级别（root/admin vs 普通用户）。
3. 访问路径（本地控制台、SSH、RDP、tailnet）。
4. 网络暴露（公网 IP、反向代理、隧道）。
5. OpenClaw gateway 状态和绑定地址。
6. 备份系统和状态（如 Time Machine、系统镜像、快照）。
7. 部署上下文（本地 Mac 应用、无头 gateway 主机、远程 gateway、容器/CI）。
8. 磁盘加密状态（FileVault/LUKS/BitLocker）。
9. OS 自动安全更新状态。
   注：这些不是阻断项，但强烈建议启用，尤其是当 OpenClaw 可访问敏感数据时。
10. 具有完全访问权限的个人助手的使用模式（本地工作站 vs 无头/远程 vs 其他）。

首先请求一次运行只读检查的权限。如果获准，默认运行并仅针对无法推断或验证的项目提问。不要询问运行时或命令输出中已可见的信息。请求权限时用一句话表达，后续所需信息列为无序列表（不编号），除非是要展示可选选项时才编号。

如必须询问，使用非技术性提示：

- "你使用的是 Mac、Windows PC，还是 Linux？"
- "你是直接在这台机器上操作，还是从另一台电脑连接？"
- "这台机器可以从公网访问，还是只在家庭/内部网络中使用？"
- "你是否启用了备份（如 Time Machine），且备份是最新的？"
- "磁盘加密是否已开启（FileVault/BitLocker/LUKS）？"
- "自动安全更新是否已启用？"
- "你是如何使用这台机器的？"
  示例：
  - 与助手共享的个人机器
  - 专用于助手的本地机器
  - 远程访问的专用机器/服务器（始终开机）
  - 其他？

只在了解系统上下文后才询问风险偏好。

如果用户授权只读操作，默认运行适合该 OS 的检查。如果未授权，提供选项（编号）。示例：

1. OS：`uname -a`、`sw_vers`、`cat /etc/os-release`。
2. 监听端口：
   - Linux：`ss -ltnup`（或若 `-u` 不支持则用 `ss -ltnp`）。
   - macOS：`lsof -nP -iTCP -sTCP:LISTEN`。
3. 防火墙状态：
   - Linux：`ufw status`、`firewall-cmd --state`、`nft list ruleset`（选择已安装的那个）。
   - macOS：`/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate` 和 `pfctl -s info`。
4. 备份（macOS）：`tmutil status`（如使用 Time Machine）。

### 2）运行 OpenClaw 安全审计（只读）

作为默认只读检查的一部分，运行 `openclaw security audit --deep`。仅在用户请求时提供替代方案：

1. `openclaw security audit`（更快，不做探测）
2. `openclaw security audit --json`（结构化输出）

提供应用 OpenClaw 安全默认值的选项（编号）：

1. `openclaw security audit --fix`

明确说明 `--fix` 只加固 OpenClaw 默认值和文件权限。它不更改主机防火墙、SSH 或 OS 更新策略。

如果浏览器控制已启用，建议在所有重要账户上启用 2FA，优先使用硬件密钥，短信不足以保证安全。

### 3）检查 OpenClaw 版本/更新状态（只读）

作为默认只读检查的一部分，运行 `openclaw update status`。

报告当前频道及是否有可用更新。

### 4）确定风险容忍度（了解系统上下文后）

请用户选择或确认风险态势以及所需的开放服务/端口（以下编号选项）。
不要强制归入固定方案；如用户愿意，捕获需求而非选择方案。
提供建议方案作为可选默认值（编号）。注意大多数用户选择家庭/工作站均衡方案：

1. 家庭/工作站均衡（最常见）：防火墙开启并配置合理默认值，远程访问限于 LAN 或 tailnet。
2. VPS 加固：默认拒绝入站防火墙，最小开放端口，仅密钥 SSH，禁止 root 登录，自动安全更新。
3. 开发者便利：允许更多本地服务，明确暴露警告，仍然审计。
4. 自定义：用户定义的约束（服务、暴露、更新节奏、访问方式）。

### 5）制定修复方案

提供包含以下内容的方案：

- 目标方案
- 当前态势摘要
- 与目标的差距
- 含精确命令的逐步修复方案
- 访问保留策略和回滚方案
- 风险和潜在锁定场景
- 最小权限说明（如避免管理员使用，在安全情况下收紧所有权/权限）
- 凭证卫生说明（OpenClaw 凭证位置，优先磁盘加密）

始终在任何变更之前显示方案。

### 6）提供执行选项

提供以下选项之一（编号，方便用户用单个数字回复）：

1. 帮我执行（引导式，逐步审批）
2. 仅显示方案
3. 只修复关键问题
4. 导出命令供后续使用

### 7）带确认执行

对每个步骤：

- 显示精确命令
- 解释影响和回滚方式
- 确认访问仍可用
- 遇到意外输出时停止并寻求指导

### 8）验证并报告

重新检查：

- 防火墙状态
- 监听端口
- 远程访问仍然可用
- OpenClaw 安全审计（重新运行）

提交最终态势报告，并记录所有延迟处理的项目。

## 必需确认（始终）

以下操作需要明确批准：

- 防火墙规则更改
- 开放/关闭端口
- SSH/RDP 配置更改
- 安装/卸载软件包
- 启用/禁用服务
- 用户/组修改
- 调度任务或启动持久化
- 更新策略更改
- 访问敏感文件或凭证

如有疑问，请询问。

## 定期检查

OpenClaw 安装或首次加固后，至少运行一次基线审计和版本检查：

- `openclaw security audit`
- `openclaw security audit --deep`
- `openclaw update status`

建议持续监控。使用 OpenClaw cron 工具/CLI 安排定期审计（Gateway 调度器）。未经明确批准不要创建调度任务。将输出存储在用户批准的位置，避免在日志中记录密钥。
安排无头 cron 运行时，输出中应包含提示用户调用 `healthcheck` 以便修复问题的说明。

### 调度必需提示（始终）

每次审计或加固后，明确提供调度选项并要求直接回应。使用简短提示（编号）：

1. "你希望我通过 `openclaw cron add` 安排定期审计（如每日/每周）吗？"

如果用户同意，询问：

- 节奏（每日/每周）、首选时间窗口和输出位置
- 是否也调度 `openclaw update status`

使用稳定的 cron 任务名称以确保更新具有确定性。优先使用精确名称：

- `healthcheck:security-audit`
- `healthcheck:update-status`

创建前，先运行 `openclaw cron list` 并按精确 `name` 匹配。如果找到，使用 `openclaw cron edit <id> ...`。
如果未找到，使用 `openclaw cron add --name <name> ...`。

还提供定期版本检查以便用户决定何时更新（编号）：

1. `openclaw update status`（源代码检出和频道的首选方式）
2. `npm view openclaw version`（已发布的 npm 版本）

## OpenClaw 命令准确性

仅使用已支持的命令和标志：

- `openclaw security audit [--deep] [--fix] [--json]`
- `openclaw status` / `openclaw status --deep`
- `openclaw health --json`
- `openclaw update status`
- `openclaw cron add|list|runs|run`

不要发明 CLI 标志，也不要暗示 OpenClaw 强制执行主机防火墙/SSH 策略。

## 日志和审计跟踪

记录：

- Gateway 身份和角色
- 方案 ID 和时间戳
- 已批准的步骤和精确命令
- 退出码和已修改的文件（尽力而为）

屏蔽密钥。不要记录 token 或完整的凭证内容。

## 内存写入（有条件）

仅当用户明确选择加入且会话是私人/本地工作空间时，才写入内存文件
（参考 `docs/reference/templates/AGENTS.md`）。否则提供经过脱敏的、可粘贴的摘要，由用户决定是否保存到其他地方。

遵循 OpenClaw 压缩使用的持久内存提示格式：

- 将持久性说明写入 `memory/YYYY-MM-DD.md`。

每次审计/加固后，如已选择加入，向 `memory/YYYY-MM-DD.md` 追加简短的日期摘要（检查了什么、关键发现、采取的行动、任何已调度的 cron 任务、关键决策以及所有执行的命令）。仅追加：不覆盖现有条目。
屏蔽敏感主机详情（用户名、主机名、IP、序列号、服务名称、token）。
如有持久偏好或决策（风险态势、允许的端口、更新策略），也更新 `MEMORY.md`（长期内存是可选的，仅在私人会话中使用）。

如果会话无法写入工作空间，请求权限或提供用户可粘贴到内存文件中的精确条目。
