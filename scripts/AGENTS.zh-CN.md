# 脚本指南

此目录管理本地工具、脚本封装和生成产物的辅助规则。

## 封装规则

- 当代码库已有精心设计的接缝时，优先使用现有封装，而非直接调用原始工具入口。
- 对于测试，优先使用 `scripts/run-vitest.mjs` 或根目录 `pnpm test ...` 入口，而非直接调用 `vitest run`。
- 对于代码检查/类型检查流程，在新增或编辑应遵守代码库本地运行时行为的包脚本或 CI 步骤时，优先使用 `scripts/run-oxlint.mjs` 和 `scripts/run-tsgo.mjs`。
- 对于变更文件验证，优先使用 `scripts/check-changed.mjs`，并将通道分类保留在 `scripts/changed-lanes.mjs` 中。不要将路径作用域规则复制到新的钩子或临时 CI 片段中。

## 本地重量级检查锁

- 遵守 `scripts/lib/local-heavy-check-runtime.mjs` 中的本地重量级检查锁定行为。
- 不要为了让本地循环看起来更快而绕过真实重量级命令的锁定。
- 仅当现有辅助逻辑表明安全时，纯元数据或明确范围的命令才可跳过锁定。
- 如果更改了锁定启发规则，请在 `test/scripts/` 下添加或更新相应的窄测试。

## 生成产物

- 如果脚本生成产物，请保持源头生成器、包脚本和匹配的验证/检查命令三者一致。
- 优先使用可加性的生成器/检查器对，如 `*:gen` 和 `*:check`，而非一次性的无文档脚本。

## 作用域

- 将脚本运行器行为、封装期望和生成产物指引保留在此处。
- 将代码库全局验证策略留在根目录 `AGENTS.md` 中。
